# 抽卡规划台 v1 产品与技术设计

核验日期：2026-09-18（Asia/Hong_Kong）。目标：本地优先的《绝区零》限定角色/音擎资源规划；绝不要求游戏账号、密码或付费。

## 页面与流程

总览 → 资源 → 卡池状态 → 目标 → 时间轴/收入 → 概率 → 方案比较 → 数据来源 → 设置。手机使用底部导航，桌面使用侧栏。所有输入即时校验，删除及清空二次确认。深色与浅色、高对比文字和明确数字标签。

## 数据模型

`AppData`（带 schemaVersion）包含资源、各频道状态、规则覆盖、时间轴、收入和多个 `Plan`；`Plan` 包含有序 `Target`，每个目标有频道、数量、单目标限额、结束日期、继续标志及跳过标志。频道状态含垫数、限定保证、上次 S 结果。收入含起止日期、重复周期、确定性与启用状态。日期以本地日历日计算。

## 概率算法

规则文件定义硬保底、限定 S 分支概率、逐抽 S 概率曲线、歪后保证与跨目标继承开关。每一抽把状态 `(垫数, 限定保证, 已获数量, 已投入)` 转移；获得 S 后垫数重置，是否在歪后打开保证由配置决定。目标达成、单目标限额和按日期可用资源限制为吸收边界。计划的精确算法传播按投入抽数和两个频道状态分组的概率质量，直到所有目标完成或停止。实际计划消耗分位数包含失败停止；另计算联合成功概率的 75/90/95% 累计覆盖线，总成功率不足阈值时显示不可达。若关闭歪后保证且限定概率小于 100%，目标没有有限的理论最坏需求。Monte Carlo 使用独立可复现的随机流，Wilson 区间检验联合成功率。金额预算不被转换成抽数，除非用户主动录入可兑换资源。

官方基础概率、综合概率、硬保底、限定分支和歪后保证已经由当前官方概率 JSON 核验。官方没有披露逐抽递增曲线，默认逐抽阶梯使用可独立停用的第三方拟合补丁；这是**配置模型的精确计算**，不是官方逐抽概率的精确断言。复杂方案的状态数会受上限约束，界面提示而不会显示虚假的精确值。3.2 自选 S 内容只限定非当期 S 的候选对象，不改变普通当期目标状态转移。
目标停止日期须按实际抽取顺序排列；日期倒序时阻止计算并提示用户调整，避免使用尚未到来的资源。

## 目录

`src/domain` 数据、资源和日期；`src/engine` 转移和模拟；`src/rules` 独立配置；`src/storage` IndexedDB 和迁移；`src/worker` 计算；`src/ui` 页面与图表；`tests` 单元与 E2E；`public` PWA 图标。Vite 的相对资源路径可部署到 GitHub Pages 子路径或 Cloudflare Pages 根路径。

## 不确定项

官方逐抽概率递增曲线、跨不同限定目标的歪后保证继承、特殊频道跨版本继承、后续卡池日程及未来收入仍未完全确认。独家重映/音擎回响由 `first-s-selected-v1` 独立状态机计算；普通限定的 S 级信号自选只改变歪出对象。未知未来特殊机制必须新增状态机配置，不会自动复用现有规则。
