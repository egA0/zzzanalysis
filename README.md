# ZZZ Analysis（抽卡规划台）

本地优先、无需游戏账号的《绝区零》限定角色与音擎抽卡规划工具。支持资源管理、目标排序、概率分析、方案比较与离线 PWA。

> 非官方项目，与 HoYoverse 无隶属关系。概率分析基于可配置模型，预测结果不构成抽卡或消费保证。数据核验日期和不确定项见 [数据来源](docs/SOURCES.md)。

## 网页使用指引

在线使用: https://ega0.github.io/zzzanalysis/
或按下文启动本地页面。界面默认使用简体中文。

1. **查看入门弹窗**：默认每次打开网页显示使用指引。取消勾选「下次打开网页时自动显示使用指引」后，浏览器会保存该选择；只关闭弹窗不会取消自动显示。
2. **录入当前资源**：在「当前资源」填写菲林、加密母带及可兑换副产物。原装母带不用于限定频道；金额预算不会自动折算成抽数。
3. **确认卡池状态**：在「卡池状态」分别录入角色和音擎的垫数、限定保证。特殊频道应在「特殊频道」单独配置，不要套用普通限定的保底状态。
4. **安排目标与收入**：在「目标编辑」设置目标数量、单目标限额与截止日期，按实际抽取顺序排序；在「版本资源」和「版本时间轴」核对领取进度、月卡和未来收入，避免重复计算。未来资源默认计入，可在设置中调整。
5. **阅读结果**：在「概率分析」查看整套计划完成概率、资源缺口与消耗分布，在「方案比较」比较不同安排。消耗分位数包含失败停止，不是保证成功的资源线。
6. **做好备份**：规划自动保存到当前浏览器，在「设置」可导出 JSON、导入备份。换浏览器或设备不会自动同步数据。

随时点击页面右上角的「使用指引」，或到「设置 → 使用指引」点击「打开使用指引」。设置页和弹窗都可以修改以后是否自动弹出的选择；偏好随本地数据保存，也会包含在导出备份中。清除站点数据或重置本地规划会删除规划并恢复默认指引设置。

生产站点支持离线 PWA：先在线访问并完成缓存后，可在支持的浏览器中安装或离线打开。首次加载仍需联网；安装通常需要 HTTPS 或本地开发环境。

## 功能与边界

- 分别保存角色、音擎及特殊频道状态；普通限定与特殊频道默认不共享保底状态，具体以所选规则为准。
- 根据本地卡池历史提供复刻周期与未来版本候选；预测不等于官方日程，请核对官方公告与来源日期。
- 支持按日期累计资源、可配置收入、月卡状态与抽卡副产物兑换。
- 使用精确状态转移与 Monte Carlo 模拟分析规划；「精确」仅指当前配置模型，未披露的逐抽概率不因此成为官方结论。
- 数据通过 IndexedDB 保存在当前浏览器；支持导入导出，生产构建提供离线 PWA。
- 内置卡池记录覆盖 1.0 至 3.2 的资料快照，不代表在线最新数据；未来版本资源为可配置估算，领取资格需自行确认。

## 本地开发

环境要求：Node.js 20.19+（20.x）或 22.12 及以上版本，以及 npm。克隆仓库还需要 Git。

```bash
git clone https://github.com/egA0/zzzanalysis.git
cd zzzanalysis
npm ci
npm run dev
```

打开终端输出的本地地址。后续命令均在含有 `package.json` 的项目开发目录执行。

如果你使用的工作区将开发目录和 Git 仓库分开，请先阅读工作区说明：在指定开发目录修改、安装依赖、测试、构建和预览，通过全部适用检查后再增量同步到仓库。不要把另一个目录的操作流程直接套用到当前环境。若直接在克隆的仓库中开发，则仓库根目录就是开发目录，无需另外设置同步目录。

`src/i18n/` 保留语言扩展入口，完整多语言界面尚未提供。

详细协作约定见 [贡献指南](CONTRIBUTING.md)。

## 项目结构

```text
zzzanalysis/
├── .github/workflows/   # GitHub Actions 发布流程
├── docs/               # 设计、数据来源与规则变更记录
├── public/             # 静态资源与 PWA 图标
├── scripts/            # 规则核验脚本
├── src/
│   ├── data/           # 卡池历史、版本资源与预测
│   ├── domain/         # 数据模型、资源与日期
│   ├── engine/         # 概率计算与模拟
│   ├── i18n/           # 文案与语言扩展入口
│   ├── rules/          # 规则基线与可撤销来源补丁
│   ├── storage/        # IndexedDB、迁移与本地保存
│   ├── ui/             # 页面、图表、使用指引与样式
│   └── worker/         # 后台计算入口
├── tests/              # 单元、端到端与离线测试
├── package.json
└── vite.config.ts
```

`dist/` 为构建时生成的静态站点，`node_modules/` 为本地依赖，两者都不提交到 Git。`.git/` 只保存版本控制元数据，不放置工程源码。特定工作区的本地专用指引、个人路径和生成文件不要复制到公开仓库。

## 开发与检查

只格式化本次改动的文件；`npm run format` 会格式化整个项目，使用前请确认不会产生无关改动。完成改动后执行：

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
```

页面或交互变化还要执行浏览器测试；离线缓存、PWA、静态资源或构建配置变化还要在生产构建完成后执行离线测试：

```bash
npx playwright install chromium
npm run test:e2e
npm run build
npm run test:pwa
```

已安装可用的 Playwright Chromium 时无需重复安装。`npm run preview` 预览本开发目录的 `dist/`。所有必需检查与适用检查通过后再提交或同步，失败或未运行的检查须明确说明。

### 官方规则核验

```bash
npm run verify:rules
```

需要联网，读取 HoYoverse 频道概率 JSON 并与本地官方基线比较；发现差异会失败，但不会自动改写规则。涉及官方概率依据时按需要运行；它不属于离线单元测试，也不自动更新卡池记录。默认软保底曲线是可撤销的第三方拟合模型，不是官方逐抽概率表。

## 部署

在实际开发目录完成验证；采用独立开发目录的工作区须先按指引同步工程增量。以下发布配置针对用于部署的仓库：

- **GitHub Pages**：`.github/workflows/pages.yml` 在推送到 `main` 或手动触发时执行检查、构建与发布。在仓库的 **Settings → Pages → Build and deployment** 中将发布来源设置为 **GitHub Actions**。
- **Cloudflare Pages / 其他静态托管**：项目根目录使用仓库根目录，构建命令为 `npm run build`，发布目录为 `dist`。
- Vite 使用 `base: "./"`，支持仓库子路径部署；不要把构建输出改为个人机器上的其他目录。

## 数据、隐私与问题反馈

不要求游戏账号、密码或令牌。规划与使用指引偏好保存在当前浏览器；清除站点数据会删除本地记录，请定期导出备份。

普通用户可以通过仓库 Issues 反馈问题、提出改进建议或更正文案，不需要会编程或使用 agent。请说明复现步骤、预期和实际结果、浏览器及设备信息；分享截图或脱敏后的最小示例即可。不要提交个人完整导出 JSON、访问令牌、`.env`、本地备份或账号信息。
